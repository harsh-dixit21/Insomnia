# Insomnia backend

The frontend and Node HTTP API share an origin. SQLite stores per-account workspace snapshots, optimistic revision numbers, sessions, password hashes, and append-only audit entries. Tool algorithms are shared pure modules, but execution and authoritative report creation happen through the authenticated API.

## API coverage

| Route | Responsibility |
| --- | --- |
| `GET /api/health` | Server capability and database engine status |
| `POST /api/auth/signup` | Validate account input, hash password, create empty workspace and session |
| `POST /api/auth/login` | Verify password and establish a session |
| `POST /api/auth/logout` | Revoke the current session |
| `GET /api/session` | Resolve account, CSRF token, current workspace and revision |
| `GET /api/workspace` | Read the authenticated account workspace |
| `GET /api/insights` | Compute dashboard counts, weekly activity, completion and deadline blockers from persisted data |
| `PUT /api/workspace` | Validate evaluation, workload, requirement, test, settings and deletion changes; enforce revision and immutable tool results |
| `POST /api/tools/run` | Execute one of the nine validated algorithms against saved account data; persist its result |
| `POST /api/import` | Parse workload, measurement or security-question CSV on the server |
| `POST /api/workspace/restore` | Validate backup relationships and mark historical tool outputs as imported |
| `POST /api/workspace/reset` | Replace account workspace with empty or explicit sample data |
| `GET /api/export` | Generate evaluation briefs, saved reports or a JSON backup from persisted records |
| `GET /api/audit` | Read account-isolated server audit records |

Write requests use JSON, the application request header, a session CSRF token, and a current workspace revision. Updates use a SQLite transaction and compare-and-swap revision check. The frontend does not mark a write saved before its API response arrives. Validation failures leave forms intact; stale revisions reload the server data for review.

The generic workspace mutation endpoint accepts complete domain snapshots, validates all relationships, keeps server history authoritative, and disallows creating or rewriting tool results. Reports must be generated by the tool route or explicitly imported as historical, unverified snapshots. User-entered measurements and observations are not independent attestations.

## Feature engines

Product guidance retrieves relevant official-source topics. Use-case rules expose requirements and conflicts. Deployment checks distinguish gaps, unknowns and minimum installation floors. Cost models calculate traceable cash totals. Call and demo plans use actual evaluation inputs. Questionnaire triage refuses unsupported assurances. Benchmark review computes report-level nearest-rank p95 with correctness, sample and concurrency gates. SQL review emits heuristic migration flags, not translated or executed SQL.

## Persistence and operation

Start development with `npm run dev`. Build the frontend and run `npm start` for production serving. Both modes use the same database path. SQLite's Node API requires Node.js 24.11+ for this project and currently emits an experimental-feature notice.

Database files, WAL files, and `.env` are ignored by Git. Back up the database through an appropriate SQLite backup procedure or stop the server before copying its database files. A workspace JSON backup contains domain data, not passwords or sessions. There is no automatic password-reset or email service. Keep deployment credentials and database files private.

External IOMETE execution, real company research, model-based generation, team invitations and enterprise SSO remain unconnected. Settings reports these capabilities honestly rather than simulating success.
